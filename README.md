# В рот его топтать начинаем вайбучиться 

## Проблема
- Хочется обучаться, но с какого-то момента самообучение превратилось в tutorial hell, в котором крайне тяжело понять, где правильно, а где нет. 
- Всякие скилбоксы и практикумы хотят много деняг.
- Книги уже можно считать неэффективным способом обучения для быстро развивающихся сфер (не включая всякую базу типа осей).


## Решение проблемы
ЛЛМки могут дать: 
- В целом написание курсов
- Персонализацию обучения на уровне "у меня есть изначально вот такие знания, но я хочу перейти на другой стек"
- Более углубленный и разжеванный разбор обучающего материала, если надо.
- Проверку материала заданий в роли учителя, с объяснениями "твоя реализация рабочая, но по best-practice и industry-standart лучше сделать вот так"
- Выдачу небольших подсказок для заданий в зависимости от того, где застревает обучающийся. 

## Реализация
Курсы пишутся ллмками, далее в процессе прохождения корректируются для большего понимания / углубления там где надо. На выходе уже более-менее polished курс получается.

Текущие утвержденные форматы заданий: квиз / найди ошибку / допиши код и финальный проект, который сводит весь материал вместе. Там где можно проверить задание статично - проверяется статично через тестеры. 
Там где можно реализовать статичные вменяемые подсказкии - реализуются статично. Все остальное идет через агента - всякие объяснения и углубленные проверки качества кода.

Прохождение курсов предполагается в IDE, с учетом что там уже есть все программные средства подсветки кода, рендера MD и запуска пайплайнов.
